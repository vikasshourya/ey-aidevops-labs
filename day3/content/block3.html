What is Harness?

🚀
What it istap to flip
What it is
A software delivery platform. It builds, tests, deploys and secures code from one place. Pipelines are written as YAML.
🧩
The problem it solvestap to flip
The problem it solves
Pipelines glued together from many scripts break often, differ team to team and are slow to debug. Harness gives one repeatable path from code to production.
🏢
How enterprises use ittap to flip
How enterprises use it
Platform teams publish standard pipeline templates. App teams reuse them, with approvals, policy checks and audit trails, to deploy to cloud and Kubernetes.

What AI adds
Reads a failed run and its logs, explains the cause in plain words, proposes a fix and can apply it and re-run. You still review it.

Part A: fix it yourself 15 min

The pipeline builds a tiny Python order app in two steps: test, then package.

1
🌐 BROWSERClick inside the YAML editor, press Ctrl+A, then Delete. Copy this code and paste it with Ctrl+V.
pipeline:
  stages:
    - name: build
      runtime: cloud
      platform:
        os: linux
        arch: amd64
      steps:
        - name: test
          run:
            container:
              image: python:3.12-slim
            script: |
              pip install -q pytest
              mkdir -p app tests build
              touch app/__init__.py tests/__init__.py
              cat > app/orders.py <<'EOF'
              TAX_RATE = 0.18

              def line_total(price, qty):
                  if qty <= 0:
                      raise ValueError("qty must be positive")
                  return round(price * qty, 2)

              def order_total(items):
                  subtotal = sum(line_total(p, q) for p, q in items)
                  return round(subtotal * (1 + TAX_RATE), 2)
              EOF
              cat > tests/test_orders.py <<'EOF'
              from app.orders import line_total, order_total

              def test_line_total():
                  assert line_total(10.0, 3) == 30.0

              def test_order_total_with_tax():
                  assert order_total([(100.0, 1), (50.0, 2)]) == 236.0
              EOF
              python -m pytest -q
              python -m zipfile -c build/orders-app.zip app
        - name: package
          run:
            container:
              image: python:3.12-slim
            script: |
              test -f dist/orders-app.zip || { echo "ERROR: dist/orders-app.zip not found"; ls -la; exit 1; }
              sha256sum dist/orders-app.zip > dist/SHA256SUMS
              cat dist/SHA256SUMS
2
🌐 BROWSERClick Save (the error count at the bottom should be 0). Click Run, then Run pipeline. Wait 1 to 2 minutes.
Expected: test green, package red.
⏱️ Stopwatch: manual vs AI

Part B: AI finds and fixes the first failure00:00
Start the Part A stopwatch now. Open the failed package step and its Logs. Find the error line. Then read the YAML: which folder does test write to, and which folder does package read from? Stop the stopwatch when you know.
3
🌐 BROWSERFix it. In the test step, change both places where it says build to dist:
mkdir -p app tests dist
python -m zipfile -c dist/orders-app.zip app
4
🌐 BROWSERSave, Run, Run pipeline.
Expected: both steps green. Open the package log and find the checksum line.
What just happened? build and dist are only folder names. One step wrote to one, the next looked in the other.
Part B: let Harness AI help 25 min

Same app, one more step added: a smoke-test that unzips the package and checks an order total. This version has two problems.

1
🌐 BROWSERGo to Studio → YAML. Press Ctrl+A, Delete, then paste this longer code.
pipeline:
  stages:
    - name: build
      runtime: cloud
      platform:
        os: linux
        arch: amd64
      steps:
        - name: test
          run:
            container:
              image: python:3.12-slim
            script: |
              pip install -q pytest
              mkdir -p app tests build
              touch app/__init__.py tests/__init__.py

                      raise ValueError("qty must be positive")
                  return round(price * qty, 2)

              def order_total(items):
                  subtotal = sum(line_total(p, q) for p, q in items)
                  return round(subtotal * (1 + TAX_RATE), 2)
              EOF
              cat > tests/test_orders.py <<'EOF'
              from app.orders import line_total, order_total

              def test_line_total():
                  assert line_total(10.0, 3) == 30.0

              def test_order_total_with_tax():
                  assert order_total([(100.0, 1), (50.0, 2)]) == 236.0
              EOF
              python -m pytest -q
              python -m zipfile -c build/orders-app.zip app
        - name: package
          run:
            container:
              image: python:3.12-slim
            script: |
              test -f dist/orders-app.zip || { echo "ERROR: dist/orders-app.zip not found"; ls -la; exit 1; }
              sha256sum dist/orders-app.zip > dist/SHA256SUMS
              cat dist/SHA256SUMS
        - name: smoke-test
          run:
            container:
              image: python:3.12-slim
            script: |
              mkdir /tmp/check
              python -m zipfile -e dist/orders-app.zip /tmp/check
              cd /tmp/check
              python -c "
              from app.orders import order_total
              total = order_total([(100.0, 1)])
              print('order total:', total)
              assert total == 120.0, f'expected 120.0 but got {total}'
              "
2
🌐 BROWSERSave, Run, Run pipeline.
Expected: test green, package red, smoke-test skipped. The same first problem as Part A.
3
🌐 BROWSERStart the Part B stopwatch. On the run page, in the AI chat on the left, click Analyze pipeline errors. Read the answer.
4
🌐 BROWSERCheck the AI. Open the failed package log. Find the line the AI quoted. Does it match? Stop the stopwatch.
5
🌐 BROWSERTell the AI: Yes, apply the fix and re-run. Wait for the new run.
Expected: package now green, but smoke-test red with expected 120.0 but got 118.0.
6
🌐 BROWSERClick Analyze pipeline errors again. The AI reads the new failure.
You decide: the check expects 120.0 but the app returns 118.0. Is the app wrong or the check wrong? The unit test in the test step shows which tax rate the team agreed on. If the AI offers two options, pick the one that matches that test.
7
🌐 BROWSERTell the AI to apply that fix and re-run.
Expected: all three steps green. Open the package log and find the checksum line.
