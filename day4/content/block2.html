Block 2: Build a DevOps agent (70 min)

You will: wire up a small Python agent that investigates a failing deployment with kubectl, decides it's unhealthy, proposes a rollback, waits for your yes, then acts. Everything it does is logged.

What makes it an "agent" (10 min)

observe (get_pods, get_logs, get_deployment)
  → decide (healthy or not?)
    → propose action (rollout_undo)
      → human approves
         → act (one rollout_undo)
            → audit log (who, what, why, when)

No framework. ~100 lines of Python. Two files: tools.py (what the agent can do) and agent.py (the loop + approval + LLM call).

Solo: extend the agent (30 min)

Pick one (or both if fast). Edit agent.py and/or tools.py. Keep the approval gate.

Option 1 — Tighten the approval

  • Instead of accepting yes, require the operator to type the deployment name exactly.
  • Before proposing rollout_undo, call rollout_history and REFUSE to roll back if there is only one revision (nothing to roll back to).

Option 2 — Add a check

  • Add a new tool get_recent_errors(namespace, name) that greps the deployment's logs for ERROR or 500 in the last 50 lines and returns the count.
  • Teach the system prompt to call it, and mark the deployment unhealthy if the count exceeds 5.

⭐ Takeaway

Agents are not magic. They are a small loop: observe, decide, propose, human approves, act, log. The approval gate is the whole reason a team will let an agent anywhere near production. The audit log is the whole reason a team will keep it there.
