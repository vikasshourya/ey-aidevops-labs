What is Terraform and IaC? (10 min)

Infrastructure as Code (IaC) means describing servers, networks, storage and permissions in text files instead of clicking in a portal. Terraform (HashiCorp) is the most widely used IaC tool. You declare the end state you want, and Terraform works out what to create, change or delete.

The 4 commands you will use
  • init – download the provider plugin (azurerm)
  • plan – preview the changes. Nothing is created yet
  • apply – make the changes real
  • destroy – remove everything Terraform created

Why it matters:

  • Repeatable: same file, same result in dev, test and prod
  • Reviewable: infra changes go through a pull request like application code
  • Auditable: Git history shows who changed what, and when
  • Recoverable: rebuild an environment in minutes after a disaster

How big enterprises use it: infra code lives in Git, one module library per standard (network, AKS, storage). A PR runs plan and policy checks (security, cost). A pipeline runs apply after approval. State is kept in a shared remote store with locking. Nobody changes production by hand.

Alternatives:

  • Azure: Bicep / ARM templates (Azure only)
  • AWS: CloudFormation, AWS CDK
  • Multi-cloud: Pulumi (real languages: Python, TypeScript), OpenTofu (open-source Terraform fork), Crossplane (Kubernetes-native)
  • Non-cloud / config management: Ansible, Chef, Puppet, Salt (servers and software setup). Terraform provisions the infrastructure; Ansible then configures what runs on it
Rule of thumb: Terraform (or OpenTofu) for multi-cloud and most enterprises, Bicep if you are 100% Azure, Ansible for what runs inside the servers.

Why spec-driven, not prompt-driven (10 min)

A one-line prompt — "write Terraform for Azure storage" — leaves Copilot to guess the SKU, the region, whether versioning is on, what tags you want, and the API version. You pay for those guesses in production. A short spec with numbered requirements removes the guesswork.

Keep in mind: the spec is the artifact that outlives this chat. Save it. Re-use it. Hand it to the next person on your team.
